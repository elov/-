# EEG Art

> Данные ЭЭГ, полученные в момент создания или наблюдения произведения искусства, являются искусством.

Модульный каркас для генерации произведений из данных ЭЭГ (система 10/20) с помощью клеточных автоматов и смежных методов. Каждая ветка — задокументированный, воспроизводимый маппинг «признак ЭЭГ → параметр генерации» («партитура»), а не декоративный эффект.

## Два направления

- **Наблюдение** — данные записываются во время осмотра/оценки готового произведения (например, картины).
- **Создание** — данные записываются в процессе создания произведения художником, от замысла до подписи.

Оба направления используют одно и то же ядро; отличаются только сценарий (`scenarios/`, где применимо) и источники данных (см. `ingestion/`).

## Архитектура

```
eeg_art/
├── core/            — не зависит от конкретной ветки/метода
├── ingestion/        — источники данных: синтетика, файлы, видео, взгляд
└── modules/            — ветки: каждая = feature extractor + generator (+ render)
```

### Принцип «партитуры»

Каждый генератор документирует явное соответствие признак → параметр прямо в docstring модуля. Это не факультативно: без опубликованной партитуры зритель не может отличить данные от украшения (см. разбор чужого ролика без объяснений в истории проекта — ровно та проблема, которую этот принцип решает).

### Ключевые абстракции ядра (`core/`)

| Файл | Назначение |
|---|---|
| `spatial_model.py` | Координаты электродов 10/20 (упрощённая азимутальная проекция) + интерполяция канал→поле (IDW) |
| `windowing.py` | Скользящее окно по сигналу + единый таймкод (программная замена LSL) |
| `multistream_sync.py` | Синхронизация потоков разной частоты (видео, айтрекер) по общему таймкоду |
| `field_abstraction.py` | `Grid` (2D, произвольных H×W), `Graph` (на топологии электродов), `Volume` (3D-воксели) |
| `field_sizing.py` | Форма поля, соразмерная пропорциям конкретного произведения, в рамках бюджета ячеек |
| `lenia_ops.py` | Общая механика Lenia (кольцевое ядро, bell-growth, FFT-свёртка) |
| `calibration.py` | Baseline: z-оценка признаков относительно спокойной записи |
| `dsp.py`, `pac.py`, `microstate_fit.py`, `source_model.py` | Полосовая фильтрация, Modulation Index (Tort), кластеризация микросостояний, упрощённая sLORETA |
| `registry.py`, `param_spec.py`, `config.py` | Реестр методов, типизированные параметры с обоснованием, сохранение/загрузка пресетов |
| `session_log.py`, `triptych.py`, `viz_raw.py` | Запись сессии, зальный триптих (сырые данные / признаки / генерация) |

## Реализованные ветки

| Ветка | Признак (feature extractor) | Генерация | Поле |
|---|---|---|---|
| `spectral_lenia` | band power (FFT или Welch — 2 метода) | Lenia: диапазон → параметр независимо | Grid |
| `connectivity_graph` | PLV между электродами | диффузия по графовому лапласиану + реакция | Graph |
| `microstates_regime` | класс микросостояния (k-means по GFP-пикам) | дискретная смена пресета параметров | Grid |
| `pac_coupling` | Modulation Index theta→gamma (Tort) | MI управляет **связью** фазы и амплитуды, не отдельным параметром | Grid |
| `source_volumetric` | RMS скальпа → sLORETA | 3D Lenia на воксельной сетке, рендер MIP-проекциями | Volume |
| `gaze_features` | точка фиксации айтрекера | локальное возмущение поля в точке фиксации (аналог fixation-related potentials) | условие поверх Grid |
| `palette_extraction` | k-means в Lab (main/accent цвета, раздельные счётчики) | `colorize()` красит состояние автомата палитрой | render_mapping |
| `particle_bloom` | band power (переиспользует spectral_lenia) | рой частиц с накоплением/затуханием, аттракторы на позициях электродов | canvas |
| `sonification` | band power (audification: сырой сигнал) | 2 слоя — прямой перенос частоты и 5 осцилляторов по band power | аудио |

Плюс мультикамера (`ingestion/synthetic_video.py`, `SessionLog.append_stream`) — камера на картину и камера пространства, синхронные по таймкоду с ЭЭГ.

## Реестр методов и пресеты

Внутри одной роли (например `spectral_lenia.feature_extractor`) может быть несколько взаимозаменяемых методов:

```python
from eeg_art.core.registry import MethodRegistry
MethodRegistry.list_methods("spectral_lenia.feature_extractor")  # ['fft', 'welch']
extractor = MethodRegistry.create("spectral_lenia.feature_extractor", "welch", n_segments=4)
```

Добавить новый метод — зарегистрировать класс/функцию декоратором `@MethodRegistry.register(category, name, schema=...)`, ничего не меняя в существующих методах той же роли.

Параметры описываются `ParamSpec` (граница + единицы + научное обоснование, не голое число) и сохраняются в пресет:

```python
from eeg_art.core.config import save_preset, instantiate_from_preset
save_preset("preset.json", "spectral_lenia.generator", "default", {...}, meta={"name": "calm_gallery_v1"})
gen = instantiate_from_preset("preset.json", rng=...)  # побитово воспроизводимо при одном seed
```

Сохранение вне научно обоснованного диапазона отклоняется на этапе `save_preset`.

## Поле, соразмерное произведению

По умолчанию все генераторы используют квадратное поле (`grid_size`). Чтобы задать прямоугольную форму под конкретные пропорции произведения:

```python
from eeg_art.core.field_sizing import field_shape_for_image, field_shape_for_dimensions
shape = field_shape_for_dimensions(100, 50, target_cells=220*220)  # холст 100x50см -> (H, W)
generator = ParticleBloomGenerator(spatial, field_shape=shape, ...)
```

Форма подбирается по фиксированному **бюджету ячеек**, а не по одной стороне оригинала — иначе панорамная работа могла бы непредсказуемо раздуть вычислительную стоимость.

## Работа с реальными данными

```python
from eeg_art.ingestion.file_eeg import load_ascii_eeg
data, channels = load_ascii_eeg("session.txt")  # (n_channels, n_samples), пробел-разделённый ASCII
```

**Перед тем как доверять файлу — проверьте его.** На практике встретился файл, где все 19 «каналов» коррелировали между собой на 0.998+ (реальная ЭЭГ так не выглядит никогда — лобные и затылочные источники физиологически различны) — на деле это оказался тестовый/калибровочный сигнал, продублированный во все каналы, а не запись мозга. Полезные проверки перед использованием:

- спектр (`scipy.signal.welch`) — совпадает ли заявленная полоса с реальной
- корреляция между удалёнными каналами (Fp1 vs O1/O2) — должна быть заметно ниже 0.99
- мощность во времени — плоская запись с редкими многократными всплесками почти наверняка артефакт, а не устойчивый ритм

## Честные ограничения (задокументированы в коде, не спрятаны)

- **Проекция электродов** (`spatial_model.py`) и **forward-модель источников** (`source_model.py`) — упрощены (однородная среда, азимутальная проекция вместо MRI-based BEM/FEM). Интерфейс рассчитан на замену на MNE-Python без изменения остального пайплайна.
- **Интерполяция** — IDW, не сферический сплайн (как в EEGLAB/MNE topomap).
- **Синхронизация мультипотоков** — программная имитация роли LSL (`core/multistream_sync.py`), не настоящий LSL.
- **Baseline обязателен** для интерпретации z-оценок band power; PLV и PAC-MI нормированы по построению и baseline не требуют.

## Не реализовано (возможные следующие шаги)

- Ретрофит реестра/пресетов для оставшихся мелких утилит (`microstate_fit`, `source_model` — параметры-данные, а не скаляры)
- Настоящая интеграция LSL вместо программной синхронизации
- Замена упрощённой forward-модели на MNE + реальный монтаж/MRI
- Сценарий `creation` (session_stitching, checkpointing, stage_markers) — спроектирован, не закодирован
